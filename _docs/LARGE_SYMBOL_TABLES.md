# Bounded large Mach-O symbol tables

The original Wikipedia workflow [37975403570](https://github.com/uknes/AnyiOS/actions/runs/37975403570), head `99836c461430c0be93c87706a75153a67dcee17d`, successfully built and hashed the unchanged pinned iPhoneOS source but bundle discovery stopped at `symbol count exceeds safety limit`. Its debug dylib contains 382,495 nlist entries; WMF.framework contains 606,764. They require 22,008,418 and 48,490,638 bytes of copied names. Neither the old 100,000-entry ceiling nor the old 8 MiB name-copy budget accepted these real files.

The shared parser now permits at most 1,000,000 nlist entries and 64 MiB of aggregate copied symbol names per image. Individual names remain strictly shorter than 16,384 bytes and NUL terminated within the declared string table. Table ranges must fit the actual file before allocation. Counts, order, values, types and section indexes are retained, including local/private/debug entries; nothing is discarded to fit the budget. A repeated string offset still charges each owned name copy, preventing a small input from exceeding the allocation budget. Limits remain explicit resource policy, not a promise that all valid iOS files fit.

Guest dynamic lookup uses the same table-entry ceiling while retaining its separate 65,536-export and 8 MiB module/export-name budgets. Local/private/debug/undefined symbols remain invisible. Fallback nlist exports are counted before constructing the export snapshot, so the larger table allowance cannot bypass the export allocation bound. Neither parser acceptance nor export registration loads missing dependencies.

Local GCC inspection accepted all 15 same-run SHA-256-verified original Wikipedia ARM64 Mach-O files. The bundle probe traversed four main-process images: Wikipedia, Wikipedia.debug.dylib, RiveRuntime and WMF. It reported their unresolved external libraries and runpaths and `BUNDLE_DEPENDENCY_CLOSURE=incomplete`, with no staging or guest execution. App extensions are separate executables; parsing their files does not load them into the main process.

Portable regressions exercise more than 100,000 retained debug entries, malformed late name indexes, valid copied names exceeding the former 8 MiB cap, repeated-name allocation exhaustion, individual-name limits, forged counts, large local-table lookup visibility and export-count rejection. Local strict-warning and sanitizer builds cover this change. Windows x64 and native Windows ARM64 original intake now verify all binary identities and require the large debug and WMF tables to parse successfully. Original main-entry execution still stops at the missing loaded debug-dylib scope; no UI or API/gate promotion follows.

The public [Apple nlist ABI header](https://github.com/apple-oss-distributions/xnu/blob/main/EXTERNAL_HEADERS/mach-o/nlist.h) distinguishes debug, private, external and section symbols. The parser is independently authored; no Apple implementation is copied.
