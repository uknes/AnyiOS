# Generic ARM64 iOS executable entry — first runtime blocker only

New target anyios-general-entry-probe executes a source-verified, unprotected original ARM64 MH_EXECUTE using Dynarmic on Windows x86-64. It does not use Bitrise-specific ObjC dispatch tricks. Limits: 128 MiB binary, 384 MiB bounded guest memory, 8192 import traps, 10000 instructions. Every unresolved imported function uses a guest ARM64 trap that records the first original imported symbol and stops. No fake Foundation/UIKit/Swift implementations.

The existing Bitrise-specific probe remains separate and may execute a verified local AppDelegate BOOL IMP. General entry must not be described as equivalent to original iOS app launch: no dependent dylib initializers, original Foundation/Swift library semantics, UIKit, Windows window, native Windows ARM64 guest process, nor touch. Unknown events and loader layouts fail closed.

Security: trusted, legally redistributable source-built binaries only. This is an in-process emulator/JIT and not a sandbox for untrusted app packages. The executable never modifies its input.

Acceptance: exact unchanged pinned Bitrise original MIT ARM64 binary must stop at _objc_autoreleasePoolPush using the generic probe and record a positive bounded step count. Apply this code to the original Wikipedia ARM64 app only after its exact pinned Xcode output and dependency report are verified; any unsupported larger Mach-O or missing dyld is a blocker, not false app success.

## CI-discovered guest-memory bound defect and correction

Pinned unchanged original Bitrise generic-execution job [37865857634](https://github.com/uknes/AnyiOS/actions/runs/37865857634) failed safely before instruction execution: `FIRST_LOADER_BLOCKER=invalid guest address-space configuration`, because old `GuestMemory` enforced a **64 MiB maximum** while the new source-vetted whole-app process requires **384 MiB**. The core container now allows up to a hard cap of **512 MiB**, retains 4096-byte alignment and overflow checks, and tests rejection of 512 MiB+ inputs without allocating the excess buffer. This is not a process isolation or arbitrary/untrusted IPA security guarantee. Exact-head Windows x64 Dynarmic pinned source regression must pass before describing any original guest instructions as executed.

## First original Wikipedia runtime blocker: os_log_create

[CI 37866535015](https://github.com/uknes/AnyiOS/actions/runs/37866535015) executed 25 unchanged original ARM64 Wikipedia instructions before `_os_log_create`. Apple [declares](https://developer.apple.com/documentation/os/os_log_create) `os_log_t os_log_create(const char *subsystem, const char *category)`, with stable opaque handles. The narrow AnyiOS shim now validates bounded guest C strings, interns subsystem/category pairs, and returns unique mapped **guest** tokens; it does not expose host pointers. NO os_log_impl, ObjC semantics, release, or real logging. It fails closed on malformed arguments. The next pinned source-built Wikipedia Windows x64 run must show `SUPPORTED_NARROW_IMPORT=_os_log_create` followed by a **different** first unimplemented ABI symbol; this is a narrow trace advancement, not full iOS API completion or UIKit window.

## Wikipedia original guest getenv ABI milestone

The exact unchanged Wikipedia ARM64 binary executed 25 steps through os_log_create then reached FIRST_RUNTIME_BLOCKER=_getenv at guest step 37 in https://github.com/uknes/AnyiOS/actions/runs/37869940761. The narrow GuestEnvironment shim implements only Darwin getenv(const char *): bounded guest C-string query, read-only scan of real guest envp vector constructed by prepare_owned_process_stack, return original guest-owned value address or guest NULL for missing names. It never consults host environment or exposes host pointers. Malformed names/envp fail closed. Tests cover real owned process stack with positive/negative values, invalid guest pointers and empty guest process environment. No setenv, putenv, environment mutation, UIKit or general libc conformance is claimed. Acceptance requires original Wikipedia source-built ARM64 guest execution trace showing SUPPORTED_NARROW_IMPORT=_getenv followed by a different real blocker.

## Third measured original Wikipedia runtime blocker: os_log_type_enabled

Original source-verified Wikipedia iPhoneOS ARM64 code progressed to step 53 after handling os_log_create (step 25) and getenv (step 37). `FIRST_RUNTIME_BLOCKER=_os_log_type_enabled` in run https://github.com/uknes/AnyiOS/actions/runs/37871346086. Apple's public C ABI `bool os_log_type_enabled(os_log_t log, os_log_type_t type)` is documented at https://developer.apple.com/documentation/os/oslog/isenabled%28type%3A%29?language=objc and type constants verified in Apple XNU public log.h https://github.com/apple/darwin-xnu/blob/main/libkern/os/log.h. The restricted existing guest logger-token registry now validates token identity and type; a documented deterministic guest policy enables DEFAULT(0x00), ERROR(0x10), FAULT(0x11), disables opt-in INFO(0x01) and DEBUG(0x02), and fails closed on unknown token/type. This is a research policy, NOT a full host/system OSLog configuration mirror. No actual _os_log_impl, IPC, persistence, signposts or Apple logging daemon. Original app execution must demonstrate it moved beyond this import to a different real ABI blocker on Windows x64 Dynarmic before merge.
